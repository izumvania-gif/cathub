# CatHub — план разработки

> Мобильное веб-приложение (PWA) для семьи, чтобы вести уход за котом: кто покормил,
> когда меняли лоток, когда следующая прививка. Напоминания приходят через Telegram-бота.

Связанные документы:
- [REFERENCES.md](REFERENCES.md): конкуренты, open-source, ветеринарные нормы, технические ссылки
- [HOSTING_RU.md](HOSTING_RU.md): хостинг и сервисы, которые удобно использовать из России

---

## 1. Исходные решения

| Вопрос | Решение |
|---|---|
| Пользователи | Несколько человек, общий «дом» (household), синхронизация между телефонами |
| Коты | Один кот. В модели данных `cat_id` остаётся, чтобы потом добавить второго без миграций, но в интерфейсе выбора кота нет |
| Уведомления | Telegram-бот (подтверждено), личные сообщения и/или семейный чат. Web Push пока не делаем |
| Платформа | PWA: открывается в браузере, ставится на домашний экран iOS и Android |
| Хостинг | **Amvera, регион «Москва»**: один проект, PocketBase и бот в одном контейнере, Telegram через встроенный прокси Amvera (§8.3, [DEPLOY_AMVERA.md](DEPLOY_AMVERA.md)) |
| Язык интерфейса | Русский. Строки сразу выносим в i18n, чтобы потом можно было добавить другие языки |

## 2. Какие проблемы решаем

1. **«Кота уже покормили?»** Главная проблема, когда за котом смотрят несколько человек: кот
   получает двойную порцию или остаётся голодным. На экране «Сегодня» крупно видно, кто покормил и во сколько.
2. **Редкие дела забываются.** Прививка раз в год, обработка от паразитов раз в 1–3 месяца, полная
   замена наполнителя раз в 2 недели. У таких дел нет привычного ритма, поэтому о них нужно напоминать заранее.
3. **Непонятно, когда делали в последний раз.** Нужна история: кто, когда, заметка, значение
   (вес, препарат, номер партии вакцины).
4. **Дела распределяются неравномерно.** Статистика «кто сколько сделал» и опциональная ротация ответственного.

## 3. Функциональность

### 3.1 MVP
- **Дом и участники:** создание дома, приглашение по ссылке или коду, роли owner и member.
- **Профиль кота:** имя, фото, дата рождения, пол, порода, стерилизация, номер чипа, клиника и ветеринар.
- **Обязанности (tasks)** с гибким расписанием (§4) и набором шаблонов при онбординге (§5).
- **Экран «Сегодня»:** просроченное, дела на сегодня и дела на ближайшие дни. Одно нажатие отмечает дело
  выполненным (кнопка или свайп), затем можно отменить через undo-toast.
- **«Сделал раньше»:** отметка задним числом, например «поменял лоток вчера вечером».
- **Отложить или пропустить** выполнение с указанием причины.
- **Журнал:** лента выполнений с фильтрами по делу и по человеку.
- **Telegram-бот (MVP-минимум):** привязка аккаунта, напоминание в срок, кнопка «✅ Сделано» прямо в сообщении.

### 3.2 Следующие версии
- **Здоровье:** график веса, карточки прививок, визиты к ветеринару, курсы лекарств, фото документов
  (ветпаспорт, анализы).
- **Запасы:** корм и наполнитель. Учитываем остаток и дневной расход, считаем дату, когда запас кончится,
  и напоминаем купить заранее.
- **Статистика:** доля дел по участникам, серии (streaks), «самое просроченное».
- **Ротация ответственного** для отдельных дел (например, лоток: Маша → Петя → Маша).
- **ICS-фид:** прививки и визиты к ветеринару попадают в календарь телефона.
- **Telegram Mini App:** то же веб-приложение внутри Telegram с автологином.
- **Офлайн-режим:** отметки копятся в очереди без сети и синхронизируются позже.
- Экспорт и бэкап данных (JSON/CSV).

## 4. Модель расписаний (ядро приложения)

Всё приложение держится на расписаниях, поэтому они живут в отдельном пакете `packages/core`
как чистые функции на TypeScript, полностью покрытые unit-тестами. Один и тот же код
используют и фронтенд (показывает статусы), и бот (решает, когда напоминать).

```ts
type Schedule =
  // Дела по времени суток: кормление в 08:00 и 20:00. Каждое время — отдельный «слот».
  | { kind: 'daily_slots'; times: string[]; weekdays?: number[] }
  // Интервал: каждые N часов, дней, недель, месяцев или лет.
  | {
      kind: 'interval';
      every: number;
      unit: 'hour' | 'day' | 'week' | 'month' | 'year';
      // 'completion' — «плавающее»: следующее = последнее выполнение + интервал
      //                (лоток, когти, обработка от блох, прививки)
      // 'calendar'   — «якорное»: по сетке от startDate (например, каждое 1-е число)
      anchor: 'completion' | 'calendar';
      startDate: string;
      // Окно допуска: «когти раз в 14–21 день». Через every дело становится due,
      // через every + graceDays — overdue.
      graceDays?: number;
    }
  // Разовое дело: запись к ветеринару 12.10 в 15:30
  | { kind: 'once'; at: string };
```

**Статусы дела** считаются из расписания, последнего выполнения и текущего времени в часовом поясе дома:
`done` (выполнено для текущего слота или периода) → `upcoming` → `soon` (осталось меньше порога:
для ежедневных дел часы, для годовых 7–14 дней) → `due` → `overdue`.

**Функции ядра:**
- `nextDue(task, completions, now, tz)` → дата следующего срока
- `status(task, completions, now, tz)` → статус и сколько осталось или сколько просрочено
- `occurrences(task, from, to)` → вхождения для календаря
- `reminderPlan(task, …)` → когда и что отправить (заранее, в срок, повторы при просрочке)

**Граничные случаи для тестов:** 31 января + 1 месяц, 29 февраля + 1 год, выполнение раньше срока,
выполнение задним числом, два выполнения одного слота («двойное кормление» даёт предупреждение),
смена часового пояса дома, пропуск (skip) слота.

**Ориентиры для реализации** (подробно в [REFERENCES.md](REFERENCES.md) §2, §4.5):
`recurrence.py` из Home Keeper (MIT) — floating/fixed, `add_months` с поправкой на короткие месяцы;
режимы `every` / `every!` в Todoist; `isRolling` в Donetick (AGPL — берём только идеи, код не копируем);
журнал с флагами `skipped` / `undone` в Grocy. RRULE (RFC 5545) режим «от выполнения» не выражает,
поэтому храним свой формат `Schedule`, а RRULE используем только для экспорта в ICS.

`nextDue` в базе не храним: его всегда можно вычислить из расписания и последнего выполнения. Для дома
с одним котом это пара десятков дел, так что пересчёт ничего не стоит, а рассинхрона между
клиентом и ботом не будет.

## 5. Шаблоны дел по умолчанию

При онбординге пользователь отмечает галочками нужные дела, и частоты сразу можно поправить.
Значения ниже — стартовые. Ссылки на источники собраны в [REFERENCES.md](REFERENCES.md) §3.
Медицинские интервалы (прививки, антипаразитарные препараты) в интерфейсе подписаны
«уточните у ветеринара / по инструкции препарата».

| Категория | Дело | Расписание по умолчанию | Напоминание | Основание |
|---|---|---|---|---|
| 🍽 Питание | Кормление | `daily_slots` 08:00, 20:00 | в срок + повтор через 1 ч | Cornell: 1–2 раза в день для взрослой кошки; ICC/AAFP: лучше чаще и мелкими порциями |
| 🍽 Питание | Свежая вода, мытьё мисок | каждый день | утром, если не отмечено | ASPCA |
| 🚽 Лоток | Убрать комки | `daily_slots` 09:00, 21:00 | при просрочке | AAFP/AAHA/ASPCA: минимум 1 раз в день; ICC: 2 раза в день |
| 🚽 Лоток | Полная замена наполнителя и мытьё лотка | 14 дней от выполнения (+7 дней допуска). Некомкующийся наполнитель — 7 дней | в срок | AAFP/ISFM: 1–4 недели; ICC: 2–4 недели для комкующегося |
| 🚽 Лоток | Замена фильтра фонтанчика | 28 дней от выполнения | в срок | инструкция к фонтанчику |
| ✂️ Груминг | Вычёсывание | 7 дней от выполнения (длинная шерсть — 1 день) | мягкое | ICC |
| ✂️ Груминг | Стрижка когтей | 14 дней от выполнения (+7 дней допуска) | в срок | ASPCA: 10–14 дней |
| 🦷 Груминг | Чистка зубов | 1 день (опциональное дело) | мягкое | AAHA Dental 2019: ежедневно |
| ⚖️ Здоровье | Взвешивание (со значением, кг) | 30 дней | в срок | Hill's: раз в месяц для взрослой кошки |
| 🐛 Паразиты | Обработка от блох и клещей | 30 дней от выполнения (зависит от препарата: до 12 недель) | за 1 день + в срок | CAPC |
| 🐛 Паразиты | Дегельминтизация | домашняя кошка — 180 дней; с выгулом — 90 дней | за 3 дня + в срок | ESCCAP GL1 (2025): группа A 1–2 раза в год, группа B не реже 4 раз в год |
| 💉 Прививки | Комплексная прививка (FVRCP) | 3 года от выполнения (при высоком риске — 1 год) | за 14 и за 3 дня | WSAVA 2024, AAHA/AAFP 2020 |
| 💉 Прививки | Бешенство | 1 год от выполнения | за 14 и за 3 дня | Приказ Минсельхоза № 705, практика в РФ |
| 🩺 Ветеринар | Профилактический осмотр | 1 год (с 10 лет — 6 месяцев) | за 14 дней | AAHA/AAFP 2021, AAFP Senior Care 2021 |
| 🛒 Запасы | Купить корм и наполнитель | в MVP — 30 дней, потом модуль запасов | за 3 дня | — |

При онбординге спрашиваем «Кот выходит на улицу?», «Шерсть длинная?», «Наполнитель комкующийся?»
и «Возраст» (берём из даты рождения) и по ответам подставляем интервалы.
Для редких дел сразу спрашиваем дату последнего выполнения (последняя прививка, последняя
обработка), чтобы первый срок был правильным, а не «просрочено прямо сейчас».

## 6. Экраны и UX

Нижняя навигация, 4 вкладки. Весь интерфейс рассчитан на управление одной рукой.

1. **Сегодня** (главный)
   - Шапка: фото кота, «Барсик сыт ✅ — Маша, 08:12» или «Не кормлен с 20:05 ⚠️».
   - Кольцо прогресса дня: 4 из 6 сделано.
   - Секции «Просрочено», «Сегодня», «Скоро (7 дней)».
   - Карточка дела: эмодзи-иконка, название, «через 2 дня» или «просрочено на 3 ч», аватар того,
     кто делал последним. Полоска «насколько пора» (dueness, как в Tody и Sweepy) плавно меняет цвет
     от зелёного к красному, список отсортирован по ней. Свайп вправо или тап по кругу — «сделано», затем тост «Отменить».
     Долгое нажатие открывает меню: задним числом, отложить, пропустить, заметка.
2. **Календарь.** Лента на 30 дней и годовой обзор редких дел (прививки, осмотры).
3. **Журнал.** Хронология «кто что сделал», фильтры, график веса (в фазе 3).
4. **Кот и дом.** Профиль кота, участники, приглашение, подключение Telegram, настройки дел
   (редактор расписания), тихие часы.

**Онбординг:** 3 шага. Кот (имя и фото) → шаблоны дел (галочки) → пригласить семью и подключить Telegram.

## 7. Технический стек

Цель — «современно и красиво», без лишней сложности.

**Фронтенд (`apps/web`)**
- **React 19 + TypeScript + Vite**
- **Tailwind CSS v4 + shadcn/ui** (примитивы Radix): красивые доступные компоненты, код лежит в репозитории
- **Motion** (бывший Framer Motion) для анимаций: свайп, пружинка при отметке, переходы между экранами
- **TanStack Query** для работы с API и кеша, оптимистичных апдейтов и офлайн-очереди
- **TanStack Router** или React Router для маршрутизации
- **vite-plugin-pwa** (Workbox): манифест, service worker, установка на домашний экран
- **date-fns** + `@date-fns/tz` с локалью `ru`
- **lucide-react** для UI-иконок, **Fluent Emoji 3D** (Microsoft, MIT) для иконок дел
- Шрифты с кириллицей: **Onest** или **Manrope** для текста, **Unbounded** для заголовков
  (раздаём сами, без Google Fonts CDN, чтобы не зависеть от доступности из РФ)
- Recharts или visx для графика веса
- Тёмная тема по `prefers-color-scheme`, safe-area insets для iPhone

**Бэкенд**
- **PocketBase**: один бинарник, SQLite, auth, realtime-подписки, файлы (фото кота, документы),
  админка, миграции в `pb_migrations`. Хватает VPS с 1 ГБ RAM, бэкап — копия одного файла.
  Realtime сразу обновляет экран «Сегодня» у всех участников, когда кто-то покормил кота.
- **Сервис бота (`apps/bot`)**: Node.js + TypeScript + **grammY**, long polling, адрес Telegram API
  задаётся через `TELEGRAM_API_ROOT` (§8.2). Ходит в PocketBase через JS SDK от имени сервисного
  аккаунта: по умолчанию `http://127.0.0.1:8090`, в одном контейнере с PocketBase. Раз в минуту вызывает
  `reminderPlan` из `packages/core` и отправляет напоминания. Обрабатывает callback-кнопки «Сделано»,
  «Отложить», «Пропустить».
  Через realtime-подписку на `completions` редактирует уже отправленные напоминания
  («✅ Петя покормил в 20:03»), чтобы никто не покормил кота второй раз.
- Авторизация: см. §8.4. Хостинг и доступ к Telegram API: см. §8.

**Монорепозиторий (pnpm workspaces)**
```
cathub/
├── apps/
│   ├── web/            # PWA (React + Vite)
│   └── bot/            # Telegram-бот + планировщик напоминаний
├── packages/
│   └── core/           # расписания, статусы, типы (чистый TS + Vitest)
├── pocketbase/
│   ├── pb_migrations/  # схема коллекций (JS-миграции)
│   └── pb_hooks/       # серверные хуки (валидация, инвайты)
├── deploy/             # entrypoint.sh (запуск PocketBase + бота в одном контейнере)
├── Dockerfile          # многоэтапная сборка: web + bot → образ с PocketBase
├── amvera.yml          # конфиг Amvera (обязательно в корне репозитория)
└── docs/
```

**Качество:** ESLint + Prettier, `tsc --noEmit`, Vitest (ядро расписаний), Playwright
(e2e в мобильном вьюпорте), GitHub Actions CI: lint → typecheck → test → build.

### 7.1 Модель данных (коллекции PocketBase)

| Коллекция | Поля |
|---|---|

| `households` | name, timezone (по умолчанию `Europe/Moscow`), invite_code, telegram_group_chat_id |

## 8. Инфраструктура и хостинг (РФ)

> Подробный разбор с источниками — в [HOSTING_RU.md](HOSTING_RU.md).

### 8.1 Что выяснилось

1. **Зарубежные платформы не подходят для пользователей в РФ.** Cloudflare замедляют с июня 2025,
   Netlify блокируют, Vercel и `*.vercel.app` работают нестабильно, GitHub Pages сбоит, Firebase
   (`web.app`) заблокирован. Российские карты эти сервисы не принимают.
   **Фронтенд и API размещаем у российского провайдера.**
2. **С российских серверов часто не достучаться до `api.telegram.org`.** С весны 2026 это касается Timeweb,
   Selectel, Reg.ru и других: подсети Telegram режутся. Для тебя как получателя Telegram работает, но
   **серверу бота нужен обходной путь**: провайдер со встроенным прокси к Telegram API (Amvera, регион
   Москва), бот в зарубежном регионе или небольшой релей за рубежом.
3. **PocketBase хорошо ложится на дешёвый хостинг.** 1 ГБ RAM хватает с запасом. Supabase self-hosted
   и Appwrite требуют от 4 ГБ.
4. **Let's Encrypt для `.ru` работает.** Летом 2026 была путаница с Subscriber Agreement v1.7, в v1.8
   формулировку смягчили. Домен лучше взять в российской зоне (`.ru` через reg.ru или nic.ru), чтобы
   не повторилась история с t.me, который сняли в реестре .ME.

### 8.2 Архитектурные следствия (для любого варианта хостинга)

- Бот — **отдельный процесс** (`apps/bot`). Сейчас он живёт в одном контейнере с PocketBase, но адрес
  PocketBase задаётся через `PB_URL`. Поэтому бота можно вынести в другой регион или к другому провайдеру,
  и он будет ходить в PocketBase по HTTPS через SDK.
- Бот работает через **long polling**, а не webhook: входящие запросы с подсетей Telegram в РФ тоже
  могут фильтроваться.
- Адрес Telegram API настраивается переменной `TELEGRAM_API_ROOT` (в grammY — опция `client.apiRoot`).
  Так один и тот же код работает напрямую, через прокси провайдера или через свой релей.
- Всё собирается в **Docker-образ** (`Dockerfile` в корне), поэтому провайдера можно сменить за вечер.
- Шрифты, иконки и SDK собираются в бандл, внешних CDN в рантайме нет. Если появится Telegram Mini App,
  SDK берём из npm, а не скриптом с `telegram.org`.
- Уведомления идут через интерфейс `Notifier`. Второй канал (Web Push, e-mail) добавляется без переделки
  бота, если Telegram станет совсем недоступен.

### 8.3 Выбор: Amvera, регион «Москва»

Подробно, с конфигами, проверками и источниками: **[DEPLOY_AMVERA.md](DEPLOY_AMVERA.md)**.

- **Один проект, один контейнер:** PocketBase (API, realtime, PWA из `pb_public`, SQLite в `/data`) и бот,
  который ходит в PocketBase по `127.0.0.1`. `amvera.yml` и `Dockerfile` лежат в корне монорепо.
  Тариф «Начальный» (290 ₽/мес) или «Начальный Плюс» (490 ₽/мес, с бэкапами `/data`).
- **Telegram идёт через встроенный прокси Amvera.** Он работает прозрачно: бот ходит на обычный
  `api.telegram.org`, `TELEGRAM_API_ROOT` пустой. В 2026 году у прокси бывали деградации, поэтому бот
  обязан переживать сетевые сбои (IPv4, ретраи, идемпотентные напоминания).
- **Этап 0 перед разработкой.** Проверить на «пустом» PocketBase SQLite (WAL) на томе `/data`, SSE через
  ingress Amvera и Telegram из контейнера.
- **Запасные планы:** бот отдельным проектом в регионе Варшава (прямой доступ к Telegram), затем свой
  relay за рубежом ([DEPLOY_YC.md](DEPLOY_YC.md) §3), затем VPS.

Рассмотренные и отклонённые варианты:

| Вариант | Почему нет |
|---|---|
| VPS в РФ + свой relay за рубежом | Два сервера, администрирование, обновления и бэкапы на нас. Остаётся запасным планом |
| Yandex Cloud (ВМ + relay) | Всё то же самое плюс больше облачной инфраструктуры. Хорошо для практики DevOps, но для хобби-проекта слишком много сложностей. Исследование сохранено в [DEPLOY_YC.md](DEPLOY_YC.md) |
| Yandex Cloud serverless | Нет готовых auth и realtime. Long polling и SQLite не живут в serverless |
| Зарубежные PaaS (Vercel, Netlify, Cloudflare, Fly.io) | Замедляются или блокируются для пользователей в РФ, российские карты не принимают |

### 8.4 Авторизация

Telegram в РФ нестабилен, поэтому **вход через Telegram основным не делаем**. Telegram только
привязывается к аккаунту для уведомлений.
- MVP: e-mail + пароль (встроено в PocketBase), приглашение в дом по ссылке.
- Позже: вход по одноразовому коду на e-mail (OTP, встроено в PocketBase, нужен SMTP: Yandex Cloud
  Postbox даёт 2 000 писем в месяц бесплатно) и VK ID (OAuth2-провайдер есть в PocketBase).
- В Telegram Mini App, если он появится, — автологин по `initData`: бот проверяет подпись и выдаёт токен
  через impersonate API PocketBase.

### Фаза 6 — Живой кот, комната, обязанности и рекомендации по возрасту

Что уже есть: у дела бывает «Любой», «Один» (`assignee`) или «По очереди» (`rotation`, сдвигается
после каждой отметки). Есть карточка «Кто сколько сделал» за 30 дней, миска с анимацией наполнения,
«спящий кот» в пустых состояниях. Этого мало, если обязанности делят по дням, а не по очереди:
нет «моих дел», нельзя подменить друг друга на один раз, никто не знает, что вы в отпуске.

#### 6.1 Пиксельный кот (основа)

- **Движок спрайтов без библиотек.** Кадры рисуем как ASCII-сетки в коде (24×24, индексы палитры),
  рендер на `<canvas>` с `image-rendering: pixelated`, масштаб целым числом (×3–×4). Палитра
  подменяется при рендере, поэтому одни и те же кадры дают любой окрас. Кадры кешируются
  в `ImageBitmap`.
- **Анимации (кадры):** идёт (4), сидит и машет хвостом (2), спит клубком и дышит (2), ест (2),
  мяукает, потягивается, умывается, прыгает, играет с клубком, недовольно сидит спиной.
- **Экономия батареи:** 8–10 кадров/с через `requestAnimationFrame` с ограничением, пауза при
  скрытой вкладке и когда кот вне экрана (`IntersectionObserver`). При `prefers-reduced-motion`
  кот не ходит, а показывает одну статичную позу своего настроения.
- **Доступность:** `role="img"` и `aria-label` с настроением: «Кузя сыт и спит». Анимация не несёт
  информации, которой нет в тексте рядом.
- **Лаборатория `/cat-lab`** (скрытый маршрут, как `/diag`): все анимации и окрасы на одном экране.
  Сначала показываю её, согласуем внешний вид, потом встраиваем.

#### 6.2 Кот на главном экране

- Полоса-«пол» над миской в карточке кормления на «Сегодня». Кот ходит туда-сюда, разворачивается
  у краёв, иногда садится, умывается, зевает. Паузы и маршрут случайные, но с сидом по дню,
  чтобы поведение не дёргалось при каждом перерендере.
- **Настроение из доски дел** (чистая функция `catMood(board, now)` в `apps/web/src/lib`, с юнит-тестами).
  Приоритет сверху вниз:

  | Состояние дел | Поведение |
  |---|---|
  | Покормили < 30 мин назад | ест у миски, потом умывается |
  | Кормление пора или просрочено | сидит у миски, мяукает (облачко «мяу?»), трогает миску лапой; чем дольше, тем настойчивее |
  | Лоток просрочен | недовольный: сидит спиной, бьёт хвостом, облачко «фу» |
  | Есть другие просроченные дела | ходит беспокойно, быстрее обычного |
  | Ночь (тихие часы или 23:00–07:00) | спит клубком, «z z z» |
  | Всё сделано на сегодня | довольный: играет с клубком, мурчит (сердечки) |
  | Иначе | спокойно гуляет, иногда садится |

  Медицинские дела (прививки, обработки) не делают кота «больным» или грустным: не пугаем.
- **Реакции на действия:** отметили кормление — кот бежит к миске; отметили лоток — прыгает;
  тап по коту — мурчит или мяукает (с лёгкой вибрацией `navigator.vibrate`, где есть).
- Коту даём больше места только если он не мешает: на узком экране и крупном шрифте полоса
  остаётся низкой, миска и «Сделано N из M» не уезжают вниз.

#### 6.3 Внешность кота

- В профиле кота (вкладка «Дом») раздел «Внешность» с живым предпросмотром:
  - окрас: рыжий, серый, чёрный, белый, кремовый, трёхцветный, черепаховый, колор-пойнт (сиамский);
  - рисунок: однотонный, полосатый (табби), пятнистый, «смокинг», «в носочках»;
  - глаза: зелёные, жёлтые, голубые, разные;
  - длина шерсти: короткая или пушистая (другой контур хвоста и щёк);
  - аксессуар: нет, ошейник (цвет), бантик, колокольчик.
- Пресеты (быстрые наборы параметров, дальше всё можно поменять), случайный окрас кнопкой «🎲»:
  1. **«Как на фото»** — коричнево-серый полосатый табби (макрель) с буквой «М» на лбу, светлым
     подбородком и грудкой, розово-коричневым носом и зелёно-жёлтыми глазами (по фото владельца);
  2. **Рыжий** табби с жёлтыми глазами;
  3. **Чёрно-белый** («смокинг»: белая грудь, мордочка и носочки);
  4. **Голубой однотонный** (британец) с медными глазами;
  5. **Трёхцветная** (белый, рыжий и чёрный пятнами);
  6. **Колор-пойнт** (сиамский) с голубыми глазами.
- Хранение: `cats.appearance` (json). Онбординг получает шаг «Какой он?» с тем же выбором
  (можно пропустить, по умолчанию серый табби).
- Тот же кот (в своём окрасе) используется в лоадере, пустых состояниях и иконке «всё сделано».

#### 6.4 Лоадер и анимации

- **Лоадер:** пиксельный кот бежит на месте, под ним «Загружаем…». Заменяет спиннер в `Suspense`,
  на старте до первой загрузки данных и при входе через Mini App. Показывается только если
  загрузка дольше 300 мс, чтобы не мигать. До загрузки профиля кот серый табби.
- **Где ещё уместно (через Motion, всё уважает reduced motion):**
  - отметка «сделано»: галочка рисуется, карточка сжимается и уезжает в «Сделано»,
    список плавно перестраивается (`layout`);
  - «Сделано N из M» — число перекатывается; всё сделано — лёгкий салют из пиксельных сердечек;
  - переходы между вкладками: короткий сдвиг и прозрачность, без задержки ввода;
  - скелетоны карточек с мерцанием вместо пустоты при первой загрузке;
  - график веса дорисовывается слева направо; бары «Кто сколько сделал» растут;
  - запасы: полоска остатка плавно убывает, при «Пополнил» — наполняется.
- Бюджет: без новых зависимостей, первая загрузка растёт не больше чем на 15 КБ gzip,
  Lighthouse Performance остаётся ≥ 90.

#### 6.5 Распределение обязанностей

Основной сценарий семьи: обязанности поделены по зонам — кто-то всегда занимается лотком, кто-то
едой; иногда меняются по дням недели.

**Зоны ответственности** (новый экран «Кто за что отвечает» во вкладке «Дом»): у каждой категории
дел (Питание, Лоток, Груминг, Паразиты, Прививки, Ветеринар, Здоровье, Покупки) — свой человек
по умолчанию и, при желании, другой на отдельные дни недели («Лоток — Петя, но по выходным Маша»).
Новые дела по умолчанию получают режим «По зоне» и берут ответственного из своей категории.
Онбординг предлагает распределить зоны сразу после приглашения семьи.

Режимы «Кто делает» в редакторе дела (переопределяют зону для конкретного дела):

| Режим | Как работает | Пример |
|---|---|---|
| **По зоне** (новый, по умолчанию) | ответственный за категорию на этот день недели | лоток → Петя |
| Любой | как сейчас: напоминание в семейный чат или всем | вода |
| Один | как сейчас | прививки — хозяин |
| По очереди | как сейчас: следующий после каждой отметки | лоток |
| **По дням недели** (новый) | у каждого дня недели свой человек | пн/ср/пт — Петя, вт/чт — Маша, выходные — любой |
| **По времени** (новый, для дел с несколькими слотами) | у каждого слота свой человек | утреннее кормление — Петя, вечернее — Маша |

- **Расчёт в ядре.** Новая чистая функция `assigneeFor(task, occurrence, ctx)` в `packages/core`:
  по режиму, дню недели и слоту в часовом поясе дома, с учётом разовых подмен и отсутствий.
  Порядок: подмена на этот срок → отсутствие (тогда «Любой») → режим дела → зона → «Любой».
  Её используют и веб, и бот. Хук ротации остаётся как есть.
- **Разовая подмена.** В меню дела и в напоминании бота: «Возьму на себя» и «Передать…» для
  конкретного срока. Коллекция `duty_overrides` (household, task, occurrence_at, user, by).
  Новый ответственный получает сообщение в Telegram: «Маша передала тебе: убрать лоток сегодня».
- **«Меня нет дома».** В профиле: период отсутствия (с–по). Коллекция `absences`
  (household, user, from, to). На это время дела человека становятся «Любой»: напоминания уходят
  в семейный чат или остальным, в интерфейсе видно «Петя в отъезде до 3 октября».
- **«Мои дела».** На «Сегодня» переключатель «Все / Мои». В «Мои» попадают дела, где я
  ответственный на этот срок, и дела «Любой». На карточке — аватар ответственного, у своих
  метка «ты». Выбор запоминается на устройстве.
- **Экран «Кто за что»** (в «Делах», вторая вкладка): неделя в виде таблицы «день × человек»
  с делами, чтобы увидеть перекос и поправить режимы в одном месте.
- **Честная нагрузка.** У дела «вес»: лёгкое (1), обычное (2), тяжёлое (3); шаблоны получают
  значения по умолчанию (вода — 1, лоток — 2, полная замена наполнителя — 3). В карточке статистики
  кроме штук показываем доли по нагрузке и план на неделю против факта.
- **Бот:** напоминание получает ответственный на этот срок. В семейном чате под напоминанием
  кнопка «🙋 Возьму»; в личке — «Передать…» со списком людей. Утренняя сводка: сначала «Твои
  сегодня», потом «Остальное».
- Отметить сделанным может любой, в журнал и статистику записывается тот, кто сделал.
  Если сделал не ответственный, ответственному приходит «✅ Маша сделала за тебя».

| `absences` | household, user, from, to, note |

Правила доступа — как у остальных: только свой `household`. Подмену и отсутствие может создать
любой участник, удалить — автор или owner. Старые данные мигрируются: `assignee` → `one`,
`rotation` → `rotation`, остальное → `anyone`.

#### 6.7 Комната кота и рыбки 🐟

Игровой слой поверх дел, без связи с реальными деньгами.

- **Рыбки зарабатываются делами.** За отметку: вес дела × 5 🐟 (лёгкое 5, обычное 10, тяжёлое 15),
  +50 % если сделано вовремя (до статуса «просрочено»), пропуск — 0. Бонус за серию: все дела дня
  сделаны N дней подряд → +10 🐟 в день серии. Рыбки за один срок дела начисляются один раз,
  так что многократные отметки не «фармят».
- **Баланс не хранится, а вычисляется** (как и сроки): сумма начислений по `completions` минус
  покупки из `room_items`. Отмена отметки автоматически забирает рыбки. Считает ядро
  (`rewards(tasks, completions, ctx)`), потому что «вовремя» — это математика расписаний.
- **Кошелёк общий на семью** (кот общий и комната общая), а в статистике видно, кто сколько
  заработал. Покупку проверяет сервер: хук `POST /api/cathub/room/buy` спрашивает баланс
  у внутреннего сервера бота (как календарь), хуки сами расписания не считают.
- **Комната.** Кот ходит не по пустой полосе, а по пиксельной комнате: пол, стена, окно.
  Покупки ставятся в слоты (пол слева/справа, стена, подоконник, у миски):

  | Предмет | Цена | Что делает кот |
  |---|---|---|
  | Клубок ниток | 30 🐟 | гоняет его, когда всё сделано |
  | Коврик | 40 🐟 | — |
  | Цветок в горшке | 50 🐟 | иногда нюхает |
  | Картина с рыбкой | 60 🐟 | — |
  | Когтеточка | 80 🐟 | точит когти |
  | Лежанка | 120 🐟 | спит в ней, а не на полу |
  | Лампа / гирлянда | 90 🐟 | вечером светится |
  | Мышка на пружинке | 70 🐟 | охотится |
  | Домик-когтеточка | 250 🐟 | залезает наверх |
  | Аквариум | 300 🐟 | сидит и смотрит на рыбок |

  Сезонные предметы (ёлка, тыква) — позже. Предметы можно переставлять и убирать на склад.
- В Telegram-напоминании после «✅ Сделано» — «+15 🐟». Утренняя сводка показывает баланс.
- Всё это отключаемо в настройках дома («Игровой режим»), если кому-то мешает.

#### 6.8 Рекомендации по здоровью по возрасту

- По дате рождения кота (есть в профиле; если не указана — просим указать) ядро выдаёт план
  `healthPlan(cat, now, history)`: что и когда сделать, с учётом уже записанного в «Здоровье».
- Правила (из `docs/REFERENCES.md`, всё с подсказкой «уточните у ветеринара»):

  | Возраст | Рекомендация |
  |---|---|
  | с 3–4 недель | дегельминтизация котёнка, дальше по схеме ветеринара |
  | за 10–14 дней до каждой прививки | глистогонка (обычная практика ветклиник в РФ перед вакцинацией) |
  | 8–9 недель | первая комплексная прививка (панлейкопения, калицивироз, ринотрахеит) |
  | 12 недель | ревакцинация комплексной + бешенство (в РФ с 3 месяцев) |
  | 16 недель | последняя доза курса котёнка, если так решит ветеринар (WSAVA: не раньше 16 недель) |
  | до 6 месяцев | взвешивание раз в 2 недели |
  | 3–7 месяцев | смена зубов: осмотреть рот, при двойном ряду — к ветеринару |
  | 5–6 месяцев | консультация о стерилизации/кастрации |
  | ~6 месяцев / 1 год | бустер после курса котёнка (WSAVA: около 26 недель) |
  | 12 месяцев | переход на корм для взрослых; дальше осмотр раз в год, бешенство ежегодно |
  | 7–10 лет | зрелая кошка: ежегодный осмотр с анализами крови |
  | старше 10 лет | осмотр не реже раза в 6 месяцев, взвешивание ежемесячно |

- На вкладке «Здоровье» блок «Сейчас по возрасту» (например, «Через месяц прививка — за 2 недели
  до неё дайте глистогонку»). Кнопки: «Добавить в дела» (создаёт дело «Один раз» с датой,
  которую можно поправить), «Уже сделано» (открывает запись здоровья) и «Скрыть».
- Когда в «Здоровье» записана прививка, рекомендации пересчитываются от её фактической даты.
- В утренней сводке бота — одна строка, если рекомендация стала актуальной на этой неделе.

#### 6.9 Тесты

- Ядро: `rewards` (вовремя/просрочено/пропуск, один раз за срок, серии, отмена), `healthPlan`
  (котёнок, взрослая, пожилая, уже сделанные прививки), `assigneeFor` для всех режимов и зон, стыки суток и недель в часовом поясе дома, подмены,
  отсутствия, пересекающиеся периоды.
- Веб (unit): `catMood` для каждой строки таблицы настроений и их приоритета; генерация кадров
  из палитры.
- E2E: кот на «Сегодня» меняет настроение (`data-mood`) после отметки кормления; внешность
  сохраняется и видна второму участнику; «Мои дела»; «По дням недели» отправляет напоминание
  нужному человеку; «🙋 Возьму» в группе; «Меня нет дома» перенаправляет напоминания.
- Axe остаётся без нарушений, Lighthouse ≥ 90, скриншоты узкого экрана и крупного шрифта.

## 11. Риски

| Риск | Что делаем |
|---|---|
| Ограничения Telegram в РФ (у получателей и у сервера) | Long polling, настраиваемый `TELEGRAM_API_ROOT`, бот — отдельный переносимый сервис. `Notifier` позволяет добавить Web Push или e-mail. Приложение работает и без бота. Для ботов в MAX нужен статус самозанятого или ИП |
| Встроенный Telegram-прокси Amvera деградирует или исчезнет | Бот переживает сбои (ретраи, outbox). Если деградации частые, выносим бота в регион Варшава. Если прокси убрали — свой relay и `TELEGRAM_API_ROOT` |
| SQLite (WAL) на сетевом томе `/data` у Amvera, перекрытие контейнеров при рестарте | Проверяем на этапе 0, пробуем `singleton`. Если что-то не так — PocketBase как Go-фреймворк с `journal_mode=DELETE` или VPS |
| Сбой всей платформы Amvera | Для семейного приложения допустимо. Docker-образ и бэкапы во внешнем S3 позволяют переехать за вечер |
| Пиксельный кот тормозит на слабых телефонах или сажает батарею | 8–10 кадров/с, пауза вне экрана и в фоне, статичная поза при reduced motion; замеряем на реальном Android |
| Сбои российских облаков при изменениях ТСПУ, «белые списки» на мобильном интернете | Принимаем как есть. Благодаря PWA-кешу приложение хотя бы открывается и показывает последние данные |
| PocketBase ещё не 1.0 | Фиксируем версию, обновляемся только после проверки на staging |
| Блокировки зарубежных CDN и хостингов | Хостим в РФ, шрифты и ассеты раздаём сами, не зависим от внешних CDN в рантайме |
| Ошибки в расчёте сроков | Ядро — чистые функции со 100% покрытием граничных случаев |
| Медицинские интервалы разные у разных препаратов | Все интервалы редактируются, в интерфейсе подсказка «уточните у ветеринара» |
| Потеря данных | Ежедневный бэкап SQLite (`pb_data`) в S3 у российского провайдера |
